# PetroLab v0.15.7 — UX consolidation backlog

Цель ветки: не добавлять новые функции, а сделать существующие функции PetroLab понятными, связанными и устойчивыми. Ниже перечислены 30 конкретных проблем, обнаруженных при ручной проверке пользовательских сценариев. Это рабочее ТЗ для v0.15.7.

## Принцип релиза

До закрытия P0/P1 не добавлять новые разделы, модули и отдельные workflow. Новая версия должна уменьшать количество экранов и способов сделать одно и то же.

## P0 — падения и разрывы основных сценариев

### 1. Duplicate Streamlit key при работе с химическим выделением
Симптом: `StreamlitDuplicateElementKey` для `v0154_clear_chemical_selection`.

Готово, когда:
- каждый интерактивный элемент получает уникальный scoped key;
- один и тот же wrapper не рендерит дублирующий элемент;
- есть E2E-тест: выделение → смена Generation/оси → сброс selection без падения.

### 2. Нет нормальной кнопки «Назад» и истории переходов
Сейчас route — одиночное значение без history stack.

Готово, когда:
- есть явная кнопка «← Назад» в основном chrome;
- хранится последние 10–20 пользовательских маршрутов;
- переход назад восстанавливает контекст выбранного набора/точек;
- авто-переходы после импорта не ломают историю.

### 3. «Недавние данные» на главной не открываются
Таблица статична, строка набора не является действием.

Готово, когда:
- клик/кнопка на строке открывает соответствующий dataset workspace;
- имя набора, Sample и source показываются человекочитаемо;
- возврат назад приводит на главную без потери контекста.

### 4. Нет единого SelectionContext
XY, multi-panel, PCA, cluster, таблицы и профили используют разные state-механизмы.

Готово, когда:
- введена единая структура `SelectionContext` по immutable `analysis_id`;
- selection можно передавать между таблицей, XY, multi-panel, PCA/cluster, профилем и Generation;
- один selection отображается одинаково во всех экранах;
- selection можно очистить одной командой.

### 5. Внутренний `analysis_id` показывается как основное имя точки
Пользователю видны длинные/технические идентификаторы.

Готово, когда:
- основная подпись точки строится как `Sample · Grain · Point · Generation`;
- ID скрыт в «Технических сведениях»;
- при отсутствии Point используется строка исходника/короткая понятная подпись, а не UUID.

### 6. При выборе точки не виден химический состав
Нельзя быстро понять, что именно выбрано.

Готово, когда:
- selection panel показывает основные идентификаторы и химические колонки;
- минимум: SiO2, TiO2, Al2O3, FeOt/FeO/Fe2O3, MgO, CaO, Na2O, K2O + доступные trace;
- список состава можно раскрыть полностью;
- hover и selection используют одинаковую идентичность точки.

### 7. Неясно, как переключаться между click / box / lasso
Сейчас пользователь зависит от Plotly toolbar.

Готово, когда:
- над интерактивным графиком есть собственный segmented control: `Точка | Прямоугольник | Лассо | Панорама`;
- активный режим визуально очевиден;
- есть короткая подсказка «выделение заменяет/добавляет текущий отбор»;
- Plotly toolbar можно сократить до вторичных функций.

### 8. После выделения нет единой панели действий
В разных экранах selection умеет разные вещи.

Готово, когда под любым selection появляется один Action Bar:
- `Создать рабочую группу`;
- `Добавить в существующую группу`;
- `Убрать из группы`;
- `Утвердить как Generation`;
- `Открыть в таблице`;
- `Открыть в нескольких графиках`;
- `Построить профиль` (если применимо);
- `Очистить выбор`.

### 9. Создание рабочей группы после выделения неочевидно
Сейчас действие различается между XY и multi-panel.

Готово, когда:
- после выделения сразу видно `Создать группу из N точек`;
- имя группы вводится рядом;
- после сохранения группа немедленно применяется на текущем и остальных связанных графиках;
- есть Undo.

### 10. Утверждение Generation после выделения неочевидно
Пользователь не понимает, где заканчивается рабочая группа и начинается интерпретация.

Готово, когда:
- Generation находится в том же Action Bar;
- PetroLab явно различает `Рабочая группа` и `Generation`;
- перед сохранением показывается число точек и основание;
- после сохранения Generation подсвечивается на всех открытых диаграммах.

## P1 — основной научный workflow

### 11. Dropdown «Группировать по» захламлён техническими и случайными колонками
Сейчас попадает почти любая categorical column.

Готово, когда:
- основной список содержит только: PetroLab Generation, исходная Generation, рабочая группа, Sample, Grain, Textural zone, источник/статья, набор, минерал;
- остальные поля доступны через `Другой столбец…`;
- внутренние/служебные поля исключены полностью.

### 12. Кластеры статистики нельзя сразу увидеть на других графиках
Cluster живёт внутри страницы Statistics.

Готово, когда:
- после расчёта есть `Показать кластеры на графиках`;
- cluster labels временно передаются через Selection/Grouping context без обязательной записи в базу;
- можно открыть 2–10 XY и увидеть те же cluster colors;
- можно сохранить выбранные кластеры как Work Groups.

### 13. Selection из PCA/кластеризации не переносится в XY
Пользователь не может проверить статистическую группу химически.

Готово, когда:
- выделенные точки PCA становятся обычным SelectionContext;
- кнопка `Проверить на XY` открывает текущий selection;
- тот же selection сохраняется при смене осей и multi-panel.

### 14. Несколько графиков сразу спрятаны в отдельном инструменте
Функция есть, но не встроена в обычный анализ.

Готово, когда:
- на обычном XY есть `+ Добавить ещё диаграмму`;
- 2–6 панелей можно создать без ухода на другую страницу;
- отдельная advanced-page может остаться, но не является обязательной.

### 15. Нельзя передать готовый XY в multi-panel
Приходится заново выбирать dataset, X/Y и группировку.

Готово, когда:
- под XY есть `Добавить этот график в набор панелей`;
- переносится PlotSpec: dataset selection, exact analysis selection, X, Y, grouping, source visibility, styles;
- добавление второй панели не сбрасывает первую.

### 16. Ручное редактирование поля через координаты вершин неприемлемо
Таблица X/Y узлов — техническая заглушка.

Готово, когда:
- основное редактирование поля: `Confidence ellipse | Convex hull | KDE`;
- доступны уровень/охват, прозрачность, толщина/тип линии;
- ручная коррекция выполняется через `добавить точки в группу / удалить точки из группы`;
- поле пересчитывается автоматически;
- координаты polygon доступны только в advanced/debug режиме.

### 17. Профиль по зерну выбирается через огромный multiselect
Нельзя нормально выбрать конкретные точки.

Готово, когда:
- профиль начинается с таблицы точек;
- первая колонка `В профиль` — checkbox;
- видны Sample, Grain, Point, Generation и химия;
- можно фильтровать по Sample/Grain/Generation;
- никакого обязательного выбора через UUID/multiselect.

### 18. Порядок точек профиля задаётся отдельно от выбора
Это разрывает физическую логику traverse.

Готово, когда:
- в той же таблице есть редактируемая колонка `Порядок`;
- drag/drop или 1..N задают последовательность;
- режимы «номер Point», «distance», «coordinates» доступны как автозаполнение порядка;
- preview профиля обновляется сразу.

### 19. Нет единого метода работы с таблицами
Таблица то display-only, то editor, то checkbox-таблица в другом разделе.

Готово, когда существует единый Table Workspace:
- выбор строк галочками;
- фильтры и поиск;
- компактный/химический/полный набор колонок;
- массовое назначение Sample/Grain/Generation/Work Group/QC;
- `Показать на графике`, `Профиль`, `Формула`, `Экспорт`;
- сохранение исходного provenance.

### 20. Расчёт формулы/APFU спрятан слишком глубоко
Пользователь должен искать отдельную вкладку.

Готово, когда:
- у dataset/selection есть кнопка `Формула / APFU`;
- на карточке точки показан status формулы и `Пересчитать`;
- после импорта доступен прямой шаг `Проверить формулы`;
- отдельная страница Formulae остаётся как расширенный режим.

## P1 — информационная архитектура и импорт

### 21. Основная навигация содержит слишком много пунктов
Пользователь видит внутреннюю структуру программы.

Готово, когда в основном sidebar остаётся примерно 7–9 пунктов:
- Главная;
- Данные;
- Графики;
- Статистика;
- Шлифы/изображения;
- Расчёты;
- Публикация;
- Поиск;
- Настройки.
Остальное — контекстные действия или advanced-tools.

### 22. «Минералогические модули» не должны быть отдельным главным пунктом
Это технический каталог возможностей.

Готово, когда:
- пункт убран из primary navigation;
- специализированные расчёты появляются внутри `Расчёты` после выбора минерала;
- каталог методов доступен через справку/advanced.

### 23. Импорт раздвоен/растроен несколькими competing workflows
Есть быстрый импорт, новые анализы, universal intake и wrappers.

Готово, когда:
- существует один вход `Добавить данные`;
- drop-zone принимает Excel/CSV + изображения;
- после анализа файла показывается один последовательный wizard;
- advanced-настройки раскрываются при необходимости, а не ведут на отдельный конкурирующий экран.

### 24. BMP не поддерживается как изображение
Лабораторные/микроскопические изображения часто приходят в BMP.

Готово, когда:
- `.bmp` принимается uploader и image service;
- валидируется Pillow;
- для web-preview при необходимости создаётся PNG preview без изменения оригинала;
- оригинальный BMP сохраняется как source asset.

### 25. Разнесение импортированных анализов по Sample неудобно
Нельзя быстро назначить разные блоки строк разным образцам.

Готово, когда:
- после preview есть шаг `Разнести по образцам`;
- можно отметить строки, диапазон или блок;
- команда `Выбранные → Sample` принимает существующий или новый Sample;
- отображается сводка `Sample → число анализов`;
- уже распознанный Sample prefilled автоматически.

### 26. Удаление/отмена неудачного импорта неочевидны
Пользователь не понимает, как убрать ошибочный dataset.

Готово, когда:
- сразу после импорта есть `Отменить этот импорт`;
- в dataset menu есть `Убрать из проекта` и `Удалить из PetroLab`;
- destructive action показывает анализы/изображения/связи;
- удаление требует подтверждения и не путается с unlink.

### 27. Внутренние mixed/phase datasets видны пользователю как обычные наборы
Pipeline implementation leak.

Готово, когда:
- один импорт воспринимается как одна пользовательская сущность;
- внутренние phase/mixed datasets скрыты или сгруппированы под import record;
- пользователь может раскрыть техническую структуру отдельно;
- поиск и recent показывают пользовательское имя импорта, а не pipeline children.

### 28. Рабочие группы недостаточно scoped по проекту
Названия групп могут приходить из всей локальной базы.

Готово, когда:
- Work Groups имеют project/workspace scope;
- список существующих групп по умолчанию показывает только текущий проект;
- cross-project reuse требует явного действия;
- одинаковое имя в разных проектах не создаёт скрытых связей.

### 29. Hover и подсказки не помогают понять действие
График зависит от знаний Plotly/Streamlit.

Готово, когда:
- hover показывает Sample · Grain · Point · Generation + X/Y + 3–6 ключевых химических значений;
- над таблицей и графиком есть короткая context-sensitive подсказка;
- пустые состояния объясняют следующий шаг;
- tooltip не показывает внутренние UUID без запроса.

### 30. Зелёные UI-тесты не проверяют реальные пользовательские сценарии
Текущие проверки ловят layout, но не workflow-разрывы.

Готово, когда есть E2E-набор минимум для сценариев:
1. Excel → разнести по двум Sample → импорт;
2. BMP → привязать к Sample/точкам;
3. таблица → выбрать строки → создать Work Group;
4. XY → box/lasso → Generation → сменить оси → selection сохранился;
5. XY → добавить как panel → второй XY;
6. PCA/cluster → открыть тот же cluster на XY;
7. таблица → выбрать 5 точек → задать порядок → профиль;
8. APFU из selection;
9. удалить ошибочный import;
10. Back после 4–5 переходов;
11. recent dataset → открыть dataset;
12. обновление/повторный рендер не создаёт DuplicateElementKey.

## Порядок реализации

### Phase A — фундамент
Закрыть 1–8, 19, 21, 23, 30. Пока они не готовы, не полировать отдельные научные экраны.

### Phase B — научная связность
Закрыть 9–18, 20, 28, 29.

### Phase C — импорт и housekeeping
Закрыть 24–27 и окончательно убрать старые/дублирующие entry points.

## Definition of Done для v0.15.7

Версия не считается готовой, пока новый пользователь без инструкции не может выполнить подряд один сценарий:

`Excel → Sample → таблица → несколько XY → выделить группу → проверить на PCA → вернуть на XY → утвердить Generation → выбрать точки профиля → APFU → сохранить рисунок`

без перехода через технические страницы, без показа внутренних ID как основных подписей и без ручного редактирования внутренних структур данных.
