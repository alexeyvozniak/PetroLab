# PetroLab — системный UX/UI аудит

Дата: 2026-08-15
Ветка: `hotfix/v0157-ux-workflow`
База аудита: `main` @ `3ef6deecd6a214e723dfa5ea37fa20ece3c9563a` (0.15.6.3)

## Резюме

Текущая проблема PetroLab не сводится к отдельным визуальным дефектам. Научное ядро и отдельные функции существуют, но пользовательский рабочий цикл распался на множество независимых экранов со своими selection-state, своими правилами группировки и разными способами продолжить одну и ту же операцию.

Главный архитектурный источник риска — накопившийся стек release-wrapper'ов. `petrolab/ui/pages/__init__.py` сначала импортирует базовые страницы, затем многократно переопределяет те же render-функции слоями v0.15.1, v0.15.2, v0.15.3, v0.15.4 и v0.15.6. Несколько этих обёрток временно monkey-patch'ят функции других модулей на время рендера. Это делает состояние Streamlit труднопредсказуемым и уже привело к runtime-падению `StreamlitDuplicateElementKey`.

До следующего функционального расширения следует провести UX-консолидацию и убрать release-wrapper stack из пользовательских сценариев.

## P0 — блокирующие проблемы

### 1. Runtime crash при химическом выделении

Пользователь воспроизвёл:

`streamlit.errors.StreamlitDuplicateElementKey: key='v0154_clear_chemical_selection'`

Причина в `petrolab/ui/workflow_continuity_v0154.py`: reusable wrapper `_advanced_interactive_with_memory` создаёт кнопку с фиксированным ключом `v0154_clear_chemical_selection`. При повторном рендере компонента в одном Streamlit tree ключ конфликтует.

Исправление:
- убрать фиксированный key из reusable component;
- ключ должен получать namespace вызывающего plot instance;
- добавить автоматический smoke-test, который реально открывает химическую разметку, делает selection и сохраняет Generation.

### 2. Release-wrapper stack / monkey-patching UI

`petrolab/ui/pages/__init__.py` многократно переопределяет `render_*` функции последующими версиями wrapper'ов. `workflow_continuity_v0154.py`, `v0151_intake_wrappers.py`, `v0152_publication_wrappers.py` и другие временно заменяют функции в импортированных модулях.

Последствия:
- невозможно локально понять, какой renderer реально работает;
- легко получить повторный render одного control;
- state keys принадлежат версиям реализации, а не пользовательским сущностям;
- одинаковые операции ведут себя по-разному в разных экранах;
- regression-тесты часто проверяют наличие строк/маршрутов, а не настоящий пользовательский сценарий.

Исправление:
- один authoritative renderer на route;
- shared components вместо monkey-patch wrappers;
- мигрировать полезную логику wrapper'ов внутрь конечных страниц/компонентов;
- удалить versioned runtime wrappers после миграции.

### 3. Нет навигационной истории

`petrolab/ui/navigation.py::navigate()` только присваивает `st.session_state['nav_route']`. Стек предыдущих страниц отсутствует.

Пользователь не может надёжно сделать «назад» после перехода Data → XY → Statistics → Generation и сохранить контекст.

Исправление:
- `NavigationState` с history stack;
- единая кнопка `← Назад` в page chrome;
- переходы должны сохранять route parameters / selection context;
- прямой переход из sidebar не должен создавать бессмысленные петли history.

### 4. Selection-state раздроблен между экранами

Сейчас одновременно существуют:
- `workflow_plot_analysis_ids`;
- `_v0151_plot_exact_analysis_ids`;
- `_v0151_multi_exact_analysis_ids`;
- `v0154_chemical_selection_ids`;
- linked-panel `*_linked_selection_ids`;
- `grain_profile_analysis_ids`;
- локальные Plotly event selections;
- статистические clusters, которые до сохранения вообще не являются общим selection.

Из-за этого нельзя естественно выполнить сценарий:

`выбрал точки → посмотрел их на 4 диаграммах → проверил PCA → вернулся → сохранил как группу → построил профиль`.

Исправление:
- один `AnalysisSelectionContext`: project_id, dataset_ids, analysis_ids, title/source, optional ordered_ids;
- все таблицы и графики читают/обновляют один selection context;
- selection можно сохранить как named Work Group, но для временного просмотра это не обязательно.

### 5. Внутренние ID выставлены пользователю вместо научной идентичности

Примеры:
- Generation manager формирует label как `group · aid[:10]`;
- grain profile добавляет `analysis_id[:8]` к названию точки;
- image point selector добавляет ID;
- workspace dataset/sample selectors показывают database id;
- dataset labels намеренно включают ID.

Immutable ID нужен внутреннему слою, но не должен быть основным пользовательским названием.

Исправление:
- default label: `Sample · Grain · Point · Generation`;
- source row / dataset только вторичной серой строкой;
- UUID/DB id только в «Технические сведения»;
- если scientific identity не уникальна — автоматически добавлять понятный discriminator (лист/строка), а не UUID.

### 6. Нет единого табличного способа работы с анализами

Большинство таблиц — read-only `st.dataframe`. Отбор строится через фильтры, search или отдельные multiselect. `batch_actions` единственный использует checkbox table, но показывает `_analysis_id` и не показывает химический состав.

Невозможно естественно:
- отметить произвольные строки;
- увидеть рядом главные оксиды/trace;
- создать группу;
- отправить выбранное в профиль;
- построить график только по выбранным;
- сравнить выделенные строки.

Исправление: shared `AnalysisTable`:
- checkbox row selection;
- человекочитаемая точка;
- переключатели колонок `Основное / Химия / Trace / Расчёты`;
- configurable pinned Sample/Grain/Point/Generation;
- bottom action bar: `Группа`, `XY`, `Несколько графиков`, `Профиль`, `Расчёт`, `Таблица статьи`;
- selection сохраняется между экранами.

### 7. Grain profile использует неправильную модель выбора

Текущий `grain_profile.py` сначала фильтрует, затем предлагает `multiselect('Точки')`, где options — analysis_id, визуально заменённые label'ами с ID suffix. После этого порядок задаётся отдельным блоком.

Для реального traverse нужен table-first workflow:
- checkbox `В профиль`;
- Sample / Grain / Point;
- выбранные химические колонки прямо рядом;
- editable `Порядок`;
- reorder / reverse;
- preview sequence;
- затем Y variables и график.

### 8. Quick XY, Advanced XY, Multi-panel и Statistics имеют разные действия над selection

- Quick XY: можно выделить точки, но действие — только счётчик.
- Advanced XY: можно создать рабочую группу / скрыть точки.
- Multi-panel: можно сохранить Work Group или Generation.
- PCA: selection только показывает число выбранных.
- Cluster plot: selection не является общим selection; кластеры можно только массово записать как Work Groups.

Одинаковый жест selection должен иметь один и тот же action bar везде.

### 9. Кластеры статистики невозможно нормально проверить на других диаграммах

Statistics умеет записать cluster labels как `Рабочая группа`, а Multi-panel умеет группировать по Work Group. Но между этими возможностями нет workflow bridge; пользователь должен догадаться, сохранить все кластеры, перейти в другой раздел и заново настроить график.

Исправление:
- после clustering показывать `Проверить кластеры на нескольких графиках`;
- передать cluster labels как transient overlay без обязательной записи в базу;
- linked selection по cluster работает во всех панелях;
- отдельная кнопка `Сохранить выбранный cluster как рабочую группу`.

### 10. Ручной редактор полей по координатам вершин — технический интерфейс

`xy_components._field_editor()` переводит polygon в DataFrame X/Y и предлагает пользователю редактировать vertices вручную.

Это следует убрать из основного UI.

Нормальная модель:
- Work Group определяется membership точек;
- геометрия поля пересчитывается автоматически;
- пользователь выбирает `Confidence ellipse / Convex hull / KDE`, coverage/level, alpha, line width;
- ручная корректировка membership: `добавить выделенные / убрать выделенные`;
- optional expert geometry editor можно оставить только в Advanced/Developer mode.

### 11. Нет нормального перехода из одного XY в «Несколько графиков»

Single XY хранит recipe с x/y/group/filter/style. Multi-panel создаёт отдельные `multi_x_N`, `multi_y_N` state и не умеет принять текущий XY как первую панель.

Нужны действия под каждым XY:
- `Добавить как панель`;
- `Открыть этот график + ещё панели`;
- `Добавить в рисунок`.

Нужен shared `PlotSpec`, а не независимые recipe formats.

### 12. Два разных понятия «мультипанель» конфликтуют

Есть:
1. `Несколько графиков сразу` — linked chemical plots;
2. `Редактор мультипанели` — publication composer из готовых изображений/графиков.

Второй умеет принимать уже готовый multi-panel PNG, но single XY не имеет такого очевидного bridge.

Переименовать:
- `Сравнить на нескольких диаграммах`;
- `Собрать рисунок A/B/C`.

## P1 — серьёзные проблемы discoverability и workflow

### 13. Главная: «Недавние данные» не кликабельны

`home_dashboard.py` отображает список наборов обычным `st.dataframe`. Выбор строки и переход в массив отсутствует.

Сделать single-row selection + double click/open button.

### 14. Навигация перегружена

В navigation определено 47 route entries: 8 daily routes + 39 routes в «Все инструменты». Многие функции дублируются ещё и в scenario hubs.

Пользователь видит внутреннюю структуру модулей вместо задач.

Предлагаемое основное меню:
- Главная
- Данные
- Исследовать
- Шлифы / изображения
- Посчитать
- Подготовить рисунок / таблицу
- Поиск

Всё остальное — context actions и advanced drawer.

### 15. «Минералогические модули» — dead-end top-level page

`minerals.py` просто перечисляет зарегистрированные минералы и число APFU методик. Это справочная страница, а не пользовательская операция.

Убрать из основной navigation. Информацию о доступных методах показывать внутри `Расчёты` после выбора минерала.

### 16. Формулы/APFU слишком далеко от данных

Формулы находятся отдельным route `formulae`, спрятанным в «Материалы» и ещё косвенно доступны через scenario `Посчитать`.

В таблице анализов / point card должны быть действия:
- `Рассчитать APFU`;
- `Пересчитать набор`;
- `Открыть формулу`.

Если formula уже рассчитана, результат должен быть виден в той же point card.

### 17. Grouping dropdown включает технический мусор

Advanced XY и Multi-panel строят список группировки как почти все categorical columns с ограничением по cardinality. В результате пользователю предлагаются десятки служебных/малополезных колонок.

Default semantic list:
- PetroLab Generation
- исходная Generation
- Work Group
- Sample
- Grain
- Textural zone
- Source / article
- Dataset
- Mineral

Остальное — `Другой столбец…` с поиском.

### 18. Plotly selection tools не объяснены

Figure по умолчанию `dragmode='lasso'`; box/lasso/point доступны через Plotly modebar и `selection_mode`, но нет собственного очевидного переключателя PetroLab.

Добавить над plot:
`Курсор | Прямоугольник | Лассо | Сбросить выделение`.

Action hint после выбора:
`Выбрано N → Создать группу | Добавить в группу | Убрать из группы | Профиль | Скрыть`.

### 19. Удаление/отмена ошибочного импорта не обнаружимо

Нужны два разных действия:
- `Убрать из проекта` — unlink membership;
- `Удалить импорт из PetroLab` — physical delete после проверки ссылок/images/projects.

Сразу после импорта: `Отменить этот импорт`.

### 20. BMP не поддерживается

Image service и Universal Intake whitelist не включают `.bmp`, хотя Pillow уже используется для validation и способен читать BMP.

Добавить BMP upload/validation; для browser preview при необходимости конвертировать только preview в PNG in-memory, сохраняя оригинал.

### 21. Разнесение импортированных строк по Sample спрятано

Staging editor умеет range/manual assignment, но быстрый импорт его обходит. Это делает наиболее частый лабораторный сценарий неочевидным.

После preview:
`Разнести строки по Sample` как стандартный этап, если Sample отсутствует/неоднозначен.

Table interaction:
- checkbox/range selection;
- `→ существующий Sample`;
- `→ новый Sample`;
- summary counts before commit.

### 22. Нет явного user-facing lifecycle «Work Group → Generation»

Функции существуют, но расположены в разных местах. Generation manager предполагает, что Work Group уже создана, и manual selector показывает group + ID вместо chemistry.

Утверждение должно быть доступно прямо там, где группа проверяется:
`Рабочая группа N-LF candidate · 37 точек → Утвердить как Generation`.

### 23. Workspace actions работают на весь filtered scope, а не на явно выделенные строки

Object workspace передаёт все `working` rows в actions. Таблица analyses внутри workspace read-only и не создаёт row selection.

Добавить explicit table selection; action bar по умолчанию действует на выбранные строки, а `весь текущий фильтр` — отдельное осознанное действие.

### 24. Терминология смешана

UI одновременно показывает:
- Sample / Образец;
- Generation / Поколение;
- Textural zone;
- Work Group / Рабочая группа;
- Dataset / Массив / Набор;
- analysis_id.

Нужна единая русская пользовательская терминология, а canonical field names — только в technical details/import mapping.

Рекомендуемые labels:
- Образец
- Зерно
- Точка
- Текстурная зона
- Рабочая группа
- Поколение PetroLab
- Исходное поколение
- Набор анализов

### 25. Dataset/sample selectors часто показывают database id

IDs используются для предотвращения collision, но это решает внутреннюю проблему за счёт интерфейса.

Использовать stable internal value в widget options, а format_func показывать scientific label без ID. При collision добавлять source/list/row context.

## P1 — проблемы тестовой стратегии

### 26. «Full UI audit» не является настоящим full UI interaction audit

`.github/workflows/v0156-full-audit.yml` в основном запускает py_compile и unit/regression scripts.

`tests_v0155_route_stack.py` под названием route-stack проверяет наличие строк route в исходниках, а не back/forward history.

`tests_product_ui_viewports.py` browser-level, но проверяет только несколько страниц и наличие ожидаемого текста + viewport geometry. Он не проходит plot selection, group creation, cluster handoff, profile selection или formula workflow.

Нужен настоящий browser workflow suite.

### Обязательные E2E сценарии

1. Excel → разнести строки по 3 Sample → import → открыть набор.
2. Import → отменить import → данные исчезли, чужие данные сохранены.
3. BMP + TIFF + JPG → preview → привязка к Sample/points → reopen.
4. Table select 7 points → Work Group → открыть XY → те же 7 highlighted.
5. XY box selection → create group → change axes → selection/group preserved.
6. XY → `Добавить как панель` → Multi-plot с сохранённым x/y/filter/group.
7. Multi-plot lasso → Generation → no duplicate Streamlit keys.
8. Statistics clustering → выбрать cluster → открыть 4 plots → cluster highlighted.
9. Table select ordered points → profile → reorder → plot.
10. Point → APFU → result visible in point card.
11. Home recent dataset click → exact dataset workspace.
12. Data → XY → Statistics → Back → XY state restored.
13. Old running PetroLab → new installer → update succeeds.

## P2 — дальнейшее упрощение

### 27. Убрать отдельные технические страницы из пользовательского меню

Кандидаты на скрытие в Advanced/System:
- Минералогические модули
- Аналитические сессии
- Совместить EDS/EPMA/LA
- Равновесные пары
- Распределение элементов
- Редактор пород
- История правок данных
- Collaboration

Они могут оставаться доступны через context actions и advanced drawer.

### 28. Убрать дублирующие quick/advanced mental models

Quick и Advanced XY визуально выглядят как две разные программы и имеют разные selection-actions. Лучше один XY workspace:
- основной компактный toolbar;
- `Дополнительно` раскрывает outliers, publication style, envelope parameters, recipe.

### 29. Human-readable hover/point summary

Hover должен показывать:
- Sample / Grain / Point;
- Generation / Work Group;
- X/Y;
- 3–5 выбранных пользователем chemistry fields;
- source.

UUID не показывать.

### 30. Context-aware commands вместо меню страниц

Для выбранных analyses одинаковая command bar должна быть доступна в таблице, plot и statistics:

`Группа · Поколение · XY · Несколько графиков · Профиль · APFU · Термодинамика · Таблица статьи · Экспорт`

## Целевая архитектура UI

### A. `SelectionContext`
Один shared объект текущего отбора analysis IDs.

### B. `AnalysisTable`
Единая selectable table с chemistry и action bar.

### C. `PlotSpec`
Единое описание одного plot: dataset/selection/filter/x/y/group/style. Может использоваться standalone, как panel в linked comparison и как source в publication figure.

### D. `GroupContext`
Transient cluster/selection + persistent Work Group + promotion to Generation.

### E. `NavigationHistory`
Route + context stack с Back.

### F. `DatasetActions`
Open / rename / unlink / delete / undo last import.

### G. Устранение release wrappers
Все useful behavior переносится в authoritative pages/components. Versioned wrappers остаются только как миграционная история и затем удаляются из runtime.

## Критерий готовности следующей версии

Новый PetroLab считается UX-ready, если пользователь без инструкции может:

1. загрузить Excel и фотографии;
2. разнести analyses по Sample;
3. открыть импортированный dataset кликом;
4. выбрать произвольные rows в таблице;
5. создать Work Group;
6. посмотреть её на одной или нескольких диаграммах;
7. проверить кластеризацию;
8. утвердить Generation;
9. построить ordered grain profile;
10. рассчитать APFU;
11. собрать publication figure;
12. вернуться назад без потери рабочего контекста;
13. удалить ошибочный импорт.

Если для любого из этих действий приходится искать отдельный технический экран в «Все инструменты», UX-консолидация ещё не завершена.
