# PetroLab UI Design

## Цель

PetroLab должен ощущаться не как набор страниц Streamlit, а как научная рабочая среда, где пользователь начинает с объекта, данных или изображения и дальше движется по одному непрерывному контексту: найти -> открыть -> отобрать -> рассчитать -> построить -> опубликовать.

Этот документ дополняет `docs/UX_SCENARIOS.md` и задаёт конкретную композицию интерфейса для ветки `ui/task-first-shell`.

## Главный принцип

На экране в любой момент должны быть очевидны три вещи:

1. Где я нахожусь: активный проект и текущий объект/отбор.
2. Что я могу сделать прямо сейчас: 1-3 главных действия.
3. Что связано с текущим объектом: анализы, изображения, шлифы, источники, расчёты.

Внутренняя структура модулей Python не должна определять меню.

## Каркас приложения

### Левая колонка

Постоянная ширина около 248-272 px на desktop.

Сверху вниз:

- PetroLab + версия;
- активный проект;
- глобальный поиск;
- основное меню;
- текущий рабочий контекст;
- раздел `Дополнительно` для редких инструментов.

Основное меню:

1. Главная
2. Добавить данные
3. Поиск
4. Данные и выборка
5. Графики и сравнение
6. Шлифы и фото
7. Расчёты
8. Публикация
9. Настройки

### Верхняя полоса контекста

Внутри основной области, сразу над содержимым страницы:

`Проект / объект или отбор / количество анализов / источник`

Пример:

`Диссертация · Турий мыс · Флогопит · 214 анализов · 3 источника`

Справа:

- `Сбросить отбор`;
- `Построить график`;
- контекстное дополнительное действие.

Эта полоса не должна занимать больше одной строки на обычном desktop.

## Главная

Главная не является отчётным dashboard. Это стартовая площадка.

Первый экран:

- большая строка глобального поиска;
- три действия: `Добавить данные`, `Открыть последние данные`, `Продолжить текущий отбор`;
- последние 5 объектов/выборок;
- блок `Требует внимания` только если есть реальные проблемы.

Не показывать декоративные метрики ради заполнения экрана.

## Глобальный поиск

### Ввод

Одна строка:

`Найти образец, минерал, статью, шлиф, точку...`

Поиск должен понимать как минимум:

- Sample;
- Object / locality;
- mineral;
- dataset;
- Study / Source;
- thin section;
- grain;
- analytical point.

### Результат

Не четыре независимые таблицы, а одна страница объекта с четырьмя смысловыми группами:

- Объекты;
- Анализы;
- Шлифы и изображения;
- Источники.

У каждой группы виден счётчик.

Если найден один явно доминирующий объект, он открывается как workspace.

Если совпадений несколько, сначала показывается список кандидатов.

## Object Workspace

Это центральный интерфейс PetroLab.

Заголовок:

`19 ТР-1`

Под ним краткий паспорт:

- объект/местоположение;
- порода;
- Study/Source;
- число связанных анализов;
- число изображений/шлифов.

Основная область делится на две части:

### Слева 60-70%

Вкладки:

- Обзор
- Анализы
- Шлифы и фото
- Расчёты
- Источники

### Справа 30-40%

Контекстная панель:

- текущий отбор;
- быстрые фильтры;
- главные действия;
- предупреждения QC.

Ключевые действия:

- `Построить график`;
- `Сравнить`;
- `Добавить фото`;
- `Рассчитать APFU`.

## Данные и выборка

Главная задача страницы: собрать рабочий scope.

Сверху компактные фильтры:

- минерал;
- Sample;
- Generation;
- Study/Source;
- метод;
- Work Group.

Ниже большая таблица.

Над таблицей всегда видно:

`Выбрано 214 анализов из 6021`

Действия:

- `Построить график`;
- `Статистика`;
- `Сохранить выборку`;
- `Сравнить источники`.

Фильтры не изменяют исходные данные.

## Графики и сравнение

Экран делится на:

- слева: выбор X/Y/preset и компактные настройки;
- центр: сам график;
- справа: видимость групп и источников.

Панель источников должна быть полноценной частью интерфейса, а не только легендой Plotly.

Для каждого Study/Source:

- чекбокс видимости;
- число точек;
- цвет/маркер;
- команда `Показать только этот`.

Скрытие источника влияет на preview и экспорт, но не на данные и QC.

## Добавить данные

Один вход для таблиц и изображений.

### Состояние 1: пусто

Большая drop-zone:

`Перетащите Excel, CSV или фотографии`

Под ней две быстрые кнопки:

- `Выбрать таблицу`;
- `Выбрать изображения`.

### Состояние 2: распознано

Карточки файлов:

- имя;
- распознанный тип;
- размер;
- статус;
- возможность изменить тип.

### Таблица

Этапы:

1. Файл
2. Листы
3. Колонки и смысл
4. Sample / Mineral / Point / Generation
5. Проверка
6. Сохранение

Пользователь всегда видит, на каком шаге находится.

### После сохранения

Не выводить тупик `успешно`.

Показывать:

- `Открыть данные`;
- `Построить график`;
- `Добавить фотографии к этим данным`.

## Обязательный сценарий: фотография шлифа

Это P0-сценарий, а не второстепенная галерея.

### Вход A: после Excel

После импорта аналитической таблицы пользователь нажимает `Добавить фотографии к этим данным`.

PetroLab уже знает текущие datasets/Sample и предлагает их как контекст, но пользователь может изменить связь.

### Вход B: фотография отдельно

Пользователь перетаскивает одну или несколько фотографий в `Добавить данные` или `Шлифы и фото`.

### Экран привязки

Композиция desktop:

- слева 58-65%: крупное изображение;
- справа 35-42%: панель привязки;
- снизу: лента файлов текущей пачки.

Панель привязки идёт сверху вниз:

1. Что это?
   - шлиф PPL;
   - шлиф XPL;
   - BSE;
   - SEM/EDS map;
   - карта элемента;
   - макрофото образца;
   - другое.

2. К чему относится?
   - Object;
   - Sample;
   - Thin section / препарат;
   - Field;
   - Grain;
   - Generation;
   - одна точка анализа;
   - несколько точек;
   - весь dataset.

3. Выбор конкретной сущности.

4. Связанные аналитические точки.

5. Textural zone / наблюдение на изображении.

6. `Сохранить и следующее фото`.

Для batch из 10+ фотографий пользователь не должен возвращаться на предыдущую страницу. После сохранения автоматически открывается следующее изображение.

### Если точек много

Не показывать длинный multiselect из сотен ID.

Показывать:

- таблицу точек с Sample / Grain / Point / Mineral / Generation;
- строку поиска;
- checkbox selection;
- возможность `выбрать точки текущего зерна`.

### Пространственная привязка

Для шлифа/поля должна быть возможность добавить метку на изображении и связать её с одной или несколькими analytical observations.

При этом EPMA, EDS и LA-ICP-MS остаются разными наблюдениями и не смешиваются только из-за близкого положения.

### После привязки

Показывать компактное подтверждение:

`Фото связано: Sample 19 ТР-1 -> шлиф TR1-A -> Grain 7 -> точки 112, 113, 118`

Действия:

- `Следующее фото`;
- `Открыть шлиф`;
- `Показать связанные анализы`.

## Шлифы и фото

Страница строится вокруг шлифа как научного объекта, а не файловой галереи.

Левая колонка:

- список Sample / thin sections;
- поиск;
- фильтры типов изображений.

Центр:

- выбранный шлиф/поле;
- переключатель PPL/XPL/BSE/maps;
- overlays пространственных меток.

Правая панель:

- паспорт;
- связанные Grain;
- аналитические точки;
- Generation/Textural zone;
- действия `Открыть анализы`, `Добавить изображение`, `Сравнить точки`.

## Визуальная система

Сохраняем существующую спокойную научную палитру PetroLab.

Базовые токены:

- background: `#edf0ef`;
- surface: `#fbfcfb`;
- soft surface: `#f1f3f2`;
- text: `#17211f`;
- muted: `#596663`;
- border: `#cbd2cf`;
- accent: `#315f56`;
- accent hover: `#244b44`.

Шрифт: Segoe UI / Arial / sans-serif.

Не использовать стеклянные карточки, градиенты, чрезмерные тени и большие округления.

Плотность интерфейса: научная desktop-программа, а не marketing dashboard.

## Правила компонентов

- Один основной primary button в визуальном блоке.
- Вторичные действия должны быть спокойнее primary.
- Заголовок страницы + lead не должны занимать больше 90-110 px по вертикали.
- Карточка используется только для реального смыслового объекта.
- Tabs используются для разных представлений одного объекта, не для случайной группировки форм.
- Expander используется только для редких/advanced настроек.
- Ошибка должна говорить, что произошло и что делать дальше.

## Responsive

### >= 1366 px

Полный sidebar + рабочая область + контекстная правая панель.

### 1024-1365 px

Правая панель может переходить под основную область; sidebar остаётся.

### < 1024 px

Допускается свернутый sidebar. Рабочие таблицы и графики не должны искусственно ужиматься до нечитаемого состояния.

### Низкое окно

Sidebar и панели прокручиваются. Никакой текст или control не должен уменьшаться по высоте ради помещения на экран.

## Что не делаем

- не переписываем scientific core ради интерфейса;
- не переносим бизнес-логику в Streamlit page;
- не создаём отдельные несовместимые selection state на каждой странице;
- не добавляем декоративный dashboard;
- не прячем `Добавить данные`, поиск и текущий контекст в advanced меню;
- не делаем изображения второстепенным файловым приложением к анализам.

## Порядок реализации

### Этап 1

- task-first navigation;
- project/search/current-context shell;
- унификация названий действий.

### Этап 2

- Search -> Object Workspace;
- один current selection между workspace/plots/statistics.

### Этап 3

- Add Data визуально превращается в пошаговый wizard;
- отдельный photo/thin-section linking workspace;
- batch next-photo flow.

### Этап 4

- source-aware compare panel;
- publication/export continuity.

### Этап 5

- убрать obsolete CSS hotfixes после viewport regression.

## Критерий готовности

Новый shell можно считать удачным только если без знания структуры PetroLab пользователь способен выполнить три задачи:

1. найти `19 ТР-1` и открыть всё связанное;
2. добавить Excel и сразу построить график;
3. загрузить фотографию шлифа, привязать её к Sample/шлифу/зерну/точкам и затем открыть связанные анализы.
