# PetroLab: обязательные пользовательские сценарии

Этот документ фиксирует интерфейсные сценарии, которые уже были сформулированы в проекте. Они являются UX-контрактом: новый интерфейс считается удачным только если эти действия выполняются быстрее и понятнее, чем в предыдущей версии, без потери научного контекста и provenance.

## 1. Найти объект, минерал, шлиф или источник и увидеть всё связанное

Пользователь вводит в глобальный поиск название образца, минерала, шлифа, объекта или статьи.

Ожидаемое поведение:
- поиск доступен из основной оболочки, а не спрятан внутри отдельного модуля;
- результаты группируются по типам: образцы/объекты, анализы, шлифы/поля, изображения, источники/статьи;
- из результата можно одним действием открыть связанный рабочий контекст;
- для минерала можно увидеть все анализы из выбранных источников;
- поиск не меняет и не удаляет исходные данные.

Пример: найти все апатиты из одной статьи, затем добавить апатиты из другой статьи и сравнить их.

## 2. Сравнить данные из нескольких статей и временно выключать источники

Пользователь выбирает один минерал и несколько Study/Source.

Ожидаемое поведение:
- текущий отбор передаётся в график без повторного выбора тех же данных;
- источник/статья является полноценной группировкой;
- целую статью можно временно скрыть на графике без удаления данных и без изменения QC;
- скрытие источника учитывается в текущем preview и экспорте рисунка;
- состояние можно сохранить в recipe/manifest.

## 3. Добавить Excel без предварительного знания структуры PetroLab

Пользователь нажимает «Добавить данные» или перетаскивает Excel/XLSX/XLSM.

Ожидаемое поведение:
- сначала PetroLab определяет тип входных данных;
- книга проходит общий preflight;
- каждый лист показывается отдельно;
- для каждого листа можно подтвердить/исправить Mineral, Sample, Point, Generation, строку заголовка и semantic mapping;
- разные порядки элементов и оксидов допустимы;
- разные названия одних и тех же столбцов нормализуются;
- major oxides и trace elements в ppm/µg/g могут находиться в одной книге;
- неоднозначные FeO/FeOt/Fe2O3/Fe2O3t не угадываются автоматически;
- detection-limit значения сохраняются корректно;
- до сохранения показывается понятный preview и список проблем;
- после сохранения доступны действия «Открыть анализы» и «Построить график».

## 4. Добавить фотографии и привязать их к научным объектам

Пользователь загружает одну или много фотографий после импорта данных или отдельно.

Ожидаемое поведение:
- PetroLab спрашивает, что изображено и к чему привязать каждую фотографию;
- допустимые уровни связи: Object, Sample, Thin section/препарат, Field, Grain, Generation, одна точка, несколько точек, весь набор;
- при batch upload можно последовательно обработать 10+ изображений;
- тяжёлый оригинал хранится отдельно от лёгкого preview;
- потерянные связи явно показываются и не перепривязываются по номеру строки.

## 5. Работать от текущего отбора, а не заново собирать его на каждой странице

Пользователь один раз выбирает проект/набор/минерал/источники и получает рабочий контекст.

Ожидаемое поведение:
- активный проект всегда виден;
- текущий рабочий контекст виден и может быть сброшен;
- действие «Построить график» использует текущий отбор;
- переход к статистике, APFU, изображениям и публикации сохраняет релевантный scope;
- deep links и старые recipe продолжают работать.

## 6. Пересчитать минералогию и исправить неверную классификацию

Пользователь импортирует анализы, затем выполняет APFU/end-member расчёты.

Ожидаемое поведение:
- derived-результаты отделены от измеренных значений;
- при изменении исходного анализа derived-результат становится stale;
- если минерал был назначен неправильно, пользователь может исправить назначение без потери исходного анализа и provenance;
- расчёты не зависят от Streamlit UI.

## 7. Подготовить научный рисунок без разрыва рабочего процесса

Пользователь отбирает данные и строит XY/ternary/REE/spider или другой научный график.

Ожидаемое поведение:
- сначала доступен быстрый plot-first режим;
- затем можно открыть расширенные настройки;
- точки можно выбирать click/box/lasso;
- можно создавать рабочие группы и исключать точки обратимо;
- публикационные presets являются стартовой конфигурацией, а не блокировкой;
- экспорт PNG/SVG/XLSX использует текущую видимость источников и групп.

## Приоритет интерфейсных работ

P0:
1. Основная оболочка: активный проект, глобальный поиск, «Добавить данные», текущий контекст.
2. Add Data wizard: Excel и изображения как два естественных входа.
3. Search → object workspace → plot current selection.
4. Source-aware comparison и visibility.

P1:
5. Изображения и привязка к точкам/шлифам.
6. APFU/reclassification flow.
7. Publication flow.

P2:
8. Kd, thermobarometry, petrological modelling и дополнительные специализированные модули.

## Acceptance criteria для оболочки

- «Добавить данные» доступно одним кликом из основной навигации.
- Глобальный поиск виден без открытия дополнительного раздела.
- Основное меню отражает пользовательские задачи, а не внутреннюю структуру Python-модулей.
- Служебные/редкие инструменты остаются доступными, но не конкурируют с ежедневными действиями.
- Интерфейс проходит viewport tests минимум на 1920×1080, 1366×768, 1280×720 и 1024×768.
- На узком или низком окне элементы не перекрываются; sidebar прокручивается вместо сжатия текста.
- Изменения оболочки не затрагивают scientific core, repositories и формат хранения данных.
