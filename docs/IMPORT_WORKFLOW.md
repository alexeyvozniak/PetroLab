# Рабочий порядок импорта анализов

Этот документ описывает пользовательский сценарий и внутренние гарантии ПетроЛаба при импорте неоднородных Excel-файлов.

## Главное правило

ПетроЛаб не требует одинакового порядка колонок и не требует одинаковых названий служебных полей на разных листах.

Для каждого импортированного листа отдельно сохраняются:

- исходный Excel/CSV;
- имя листа;
- строка заголовков;
- исходная строка каждой аналитической точки;
- исходное имя и текущий физический номер каждой колонки;
- тип величины и единица измерения, если они однозначно распознаны;
- коэффициенты преобразования в каноническую единицу и обратно;
- подтверждённые семантические роли колонок;
- SHA-256 исходного файла.

Поэтому два листа могут иметь разный порядок оксидов, рассеянных элементов и служебных колонок.

## 1. Выбрать проект

В разделе `Источники и импорт` выберите существующий проект или предварительно создайте новый.

## 2. Выбрать способ импорта

### Связать локальный файл

Рекомендуемый режим для постоянной научной работы. Указывается полный путь к XLSX/XLSM/CSV. ПетроЛаб сохраняет связь с этим файлом и для XLSX/XLSM может записывать подтверждённые изменения обратно с резервной копией.

### Загрузить копию

Подходит, когда постоянная связь с исходным путём не нужна. ПетроЛаб сохраняет собственную управляемую копию файла.

## 3. Указать строку заголовков

Если названия колонок находятся в первой строке, оставьте `1`. Если перед таблицей есть текст или служебные строки, укажите реальную строку заголовков.

Текущая нормализация единиц рассчитана прежде всего на случай, когда название величины и единица находятся в одном заголовке (`Rb ppm`, `Rb (µg/g)`, `Rb, мкг/г`). Если единицы вынесены в отдельную строку под названиями элементов, такой лист нужно предварительно проверить в предпросмотре; программа не должна угадывать единицы из значений.

## 4. Выбрать листы и минерал

Выберите только листы с аналитическими таблицами, которые относятся к выбранному минералогическому модулю.

Если один workbook содержит разные минералы, их безопаснее импортировать отдельными партиями: сначала листы одного минерала, затем другого.

## 5. Автоматическая нормализация оксидов

Порядок оксидов не учитывается. ПетроЛаб идентифицирует величину по заголовку каждой колонки.

Например:

- `SiO2`, `SiO₂`, `SiO2 (wt. %)` → `SiO2`;
- `Al2O3`, `Al₂O₃` → `Al2O3`;
- `Na2O`, `Na₂O wt%` → `Na2O`.

Исходное имя не теряется. Внутренний `SiO2` продолжает помнить, что в конкретном Excel он назывался `SiO₂ (wt. %)` и находился, например, в пятой колонке листа.

### Железо

`FeO` и `FeOt` не считаются одной и той же величиной.

- `FeO` — отдельная величина FeO;
- `FeOt`, `FeO total`, `FeO*`, `total Fe as FeO` → внутренний `FeOt` — общее железо, выраженное как FeO.

Если отдельного `FeO` нет, `FeOt` может использоваться как FeO-equivalent в режимах пересчёта «всё Fe как Fe2+» или при последующем стехиометрическом разделении, где это предусмотрено методикой.

Комбинация `FeOt + Fe2O3` без отдельного `FeO` считается неоднозначной для структурной формулы: ПетроЛаб не должен молча складывать или вычитать эти величины и останавливает такой пересчёт с объяснением.

Если одновременно присутствуют `FeOt` и раздельные формы Fe, в предпросмотре/QC выводится предупреждение.

## 6. Рассеянные элементы и единицы

Для элементов с явно указанной массовой концентрацией ПетроЛаб использует каноническую единицу `µg/g`.

Эквивалентные варианты:

- `Rb ppm`, `Rb (µg/g)`, `Rb, мкг/г`, `Rb mg/kg` → `Rb [µg/g]` без изменения числа;
- `Ba ppb`, `Ba ng/g` → `Ba [µg/g]` с умножением на `0.001`;
- `U ppt`, `U pg/g` → `U [µg/g]` с умножением на `0.000001`.

Преобразование обратимо. Например, если исходный столбец был `Ba ppb = 1200`, в базе хранится `Ba [µg/g] = 1.2`. Если в ПетроЛабе изменить его на `2.5 µg/g`, при синхронизации в исходный Excel будет записано `2500 ppb`, а не `2.5`.

Поле `Rb` без единицы не объединяется автоматически с `Rb [µg/g]`: единицу нельзя надёжно определить по самому числу.

Если два исходных столбца приводятся к одной канонической величине, например одновременно присутствуют `Rb ppm` и `Rb (µg/g)`, они не объединяются молча. Второй получает технический суффикс вроде `Rb [µg/g]__2`, а интерфейс показывает конфликт.

## 7. Подтвердить смысловые колонки каждого листа

Для каждого выбранного листа отдельно назначаются канонические роли:

- `Sample` — образец;
- `Grain` — зерно;
- `Point` — аналитическая точка;
- `Generation` — генерация или группа кристаллизации.

Высокоуверенные варианты предлагаются автоматически:

- `Sample ID` → `Sample`;
- `Grain No` → `Grain`;
- `Spot`, `Point No` → `Point`;
- `Gen`, `Generation`, `Генерация` → `Generation`.

Неоднозначные поля (`Group`, `Type`, `Zone`, `Population`, `Series`) не становятся `Generation` автоматически. Они только показываются как возможные кандидаты и требуют ручного подтверждения.

Если после импорта высокоуверенный заголовок был безобидно переименован, например `Генерация` → `Generation`, сохранённая роль восстанавливается автоматически при обновлении.

## 8. Проверить предпросмотр

До импорта просмотрите первые строки уже после нормализации. В предпросмотре показываются:

- канонические названия оксидов;
- канонические названия рассеянных элементов;
- преобразования единиц;
- предупреждения по FeOt и конфликтующим колонкам;
- подтверждённые `Sample / Grain / Point / Generation`.

Если что-то распознано неправильно, исправьте сопоставление до импорта. Неизвестные единицы и неоднозначные химические величины программа не должна угадывать.

## 9. Импортировать

После подтверждения ПетроЛаб создаёт dataset для каждого выбранного листа и сохраняет его карту происхождения.

В единой базе разные листы объединяются по каноническим названиям независимо от исходного порядка колонок.

## 10. Загрузить фотографии и назначить связи

После импорта анализов откройте раздел `Изображения` и выберите dataset.

Можно загрузить сразу пачку изображений. ПетроЛаб показывает их последовательно: `Изображение 1 из N`, затем `2 из N` и так далее. Для каждого изображения отдельно задаются:

- тип (`BSE`, `EDS`, оптика, карта элементов, фото образца и т. д.);
- подпись;
- область связи.

Одна фотография может быть связана:

1. **с несколькими аналитическими точками одновременно** — например все EPMA/LA-ICP-MS точки, видимые на одной BSE;
2. **со значением канонического поля** — например `Sample = N-7`, `Grain = 14` или `Generation = N-X1`;
3. **со всем dataset**;
4. либо быть пропущена из текущей пачки.

При выборе точек работает поиск. Уже выбранные `_analysis_id` сохраняются при изменении строки поиска.

До физической записи файлов показывается сводка всей пачки. Сервис сначала проверяет все назначения, и только затем сохраняет изображения. Если одно из назначений некорректно, пачка не должна остаться наполовину записанной.

Физическое изображение хранится один раз. Связи с несколькими аналитическими точками находятся в отдельной many-to-many таблице, поэтому одна BSE не дублируется на диске.

## 11. Что происходит после изменения Excel вручную

ПетроЛаб сравнивает SHA-256 связанного файла с сохранённым значением. Если файл изменился, появляется статус `изменён вне ПетроЛаба`.

При обновлении dataset программа:

1. перечитывает текущий порядок колонок;
2. заново определяет их физические номера;
3. применяет или безопасно восстанавливает сохранённую семантическую карту;
4. снова приводит распознанные концентрации к каноническим единицам;
5. пересчитывает минералогические производные;
6. сопоставляет новые строки со старыми `_analysis_id`;
7. показывает, сколько ID сохранено, сколько точек появилось и сколько исчезло.

## 12. Как сохраняются ID после сортировки и вставки строк

Сопоставление выполняется консервативно, в несколько этапов.

Приоритетные уникальные ключи:

1. `Sample + Grain + Point`;
2. `Sample + Point`;
3. `Grain + Point`;
4. `Point` — только если значение уникально в обеих версиях таблицы.

Ключ применяется только если он уникален и в старой, и в новой версии dataset. Повторяющийся `Point = 1` на нескольких зернах не считается достаточным идентификатором.

Затем программа пытается найти неизменившиеся строки по точному отпечатку исходных значений. Номер Excel-строки используется только как последний fallback.

Если число строк изменилось или программа обнаружила, что точки перемещались, позиционный fallback отключается. Это защищает от наиболее опасной ошибки — случайно перенести BSE, историю изменений или другой metadata-link на чужой анализ после вставки строки.

Если надёжно определить соответствие невозможно, безопаснее создать новый `_analysis_id`, чем угадать старый. Поэтому в редком случае одновременной полной сортировки, изменения идентификаторов и изменения всех аналитических значений без устойчивого `Sample/Grain/Point` часть точек может получить новые ID. Это сознательное ограничение безопасности, а не попытка угадать соответствие.

## 13. Практическая рекомендация для новых таблиц

Если есть возможность, лучше всегда иметь хотя бы:

- `Sample`;
- `Grain`;
- `Point`.

Их порядок и исходные названия не важны: при импорте они сопоставляются с каноническими ролями. Такая тройка делает связи с фотографиями и историю анализа максимально устойчивыми даже при сортировке и вставке новых строк.
