# Пользовательские сценарии PetroLab v0.16

Этот документ описывает не список экранов, а сквозные рабочие пути. Каждый путь заканчивается понятным результатом и сохраняет provenance, метод анализа и точный состав выборки.

## Общие правила переходов

- Кнопка «Добавить» открывает один маршрут для Excel, CSV и изображений. Система уточняет тип материала после загрузки, а не заставляет заранее искать отдельный раздел.
- «Построить график» всегда передаёт точные `dataset_id` и `_analysis_id` текущего результата. Редактор графика не должен молча подменять его всей базой.
- Источник, статья, метод, Sample, поколение и рабочая группа являются фильтрами или сериями. Они не переписывают исходную строку.
- Пользователь видит разницу между исходным внешним Excel, рабочей копией PetroLab и несвязанным загруженным источником.
- Любое предупреждение объясняет, что именно требует решения и что произойдёт после выбора.

## Сценарий A. Книга Excel с несколькими листами и пакет фотографий

### Цель

Загрузить книгу, в которой на листах разный порядок столбцов и разные имена оксидов/элементов, сохранить корректные анализы, затем привязать десять фотографий к нужным точкам или оставить их неразобранными.

### Старт

Пользователь нажимает **Добавить** и перетаскивает `2024 Phlogopite.xlsx`.

### Экран 1. Карточка книги

Показываются имя файла, число листов и три состояния:

- «Нужно настроить»;
- «Готово к проверке»;
- «Требует решения».

Для каждого листа пользователь задаёт или подтверждает:

| Поле | Что выбирает пользователь |
|---|---|
| Минерал | Значение для листа или столбец, если минералы смешаны |
| Метод | EPMA/WDS, EDS, LA-ICP-MS, TIMS или «не указан» |
| Строка заголовков | Найденная строка либо ручная корректировка |
| Sample | Столбец, единое значение или заполнение позже |
| Point | Столбец с точкой, если он есть |
| Generation | Распознанный столбец или пользовательское сопоставление |
| Химия | Соответствие исходных названий `TiO2`, `TiO₂`, `TiO2 wt.%`, `La ppm`, `La µg/g` семантическим полям PetroLab |

На этом же экране отдельными жёлтыми сообщениями показываются:

- FeO/FeOt и Fe2O3/Fe2O3t, если форма железа неясна;
- неизвестные единицы trace elements;
- значения `<DL` или `<LOD`;
- дубликаты по ключу источника;
- пустой Sample, Point или Generation.

Кнопка **Проверить всю книгу** недоступна, пока есть критические неоднозначности. Проверка создаёт один общий результат: нельзя показать часть листов «успешно сохранённой», пока остальные ещё конфликтуют.

### Экран 2. Проверка и решение

Верхняя строка: «44 листа · 6 005 строк · 3 требуют решения».

Пользователь может открыть каждый конфликт. В карточке строки показываются исходное значение, интерпретация и последствия решения.

Примеры:

- `FeO` -> подтвердить «FeO» или отметить «FeOt».
- `La` без единицы -> выбрать `ppm`, `µg/g` или оставить неизвестной величиной.
- `<0.05` -> сохранить как censored value, не превращать автоматически в число.

Внизу два разных действия:

- **Сохранить в базе и рабочей копии PetroLab**;
- **Сохранить в базе и исходном Excel**.

Второе действие появляется только для реально связанного источника, предварительно проверяет SHA-256 текущего файла и сообщает о внешних изменениях. При несовпадении hash доступна только безопасная развилка: перечитать источник, сравнить изменения или создать рабочую копию. Никакой незаметной перезаписи.

### Экран 3. Фотографии после импорта

После успеха показывается вопрос: «Добавить фотографии шлифа и образца?».

Пользователь загружает пакет из десяти изображений. Для каждой карточки:

1. Выбирает тип: PPL, XPL, BSE, карта, макрофото, другое.
2. Видит подсказки по Sample и шлифу из только что импортированной книги.
3. Выбирает одну или несколько точек, зерно, поколение или весь Sample.
4. Может нажать **Оставить без связи**.

Несвязанные файлы не пропадают: они переходят в раздел **Входящие без связи** с причиной «точки не выбраны». Завершение пакета происходит одним действием **Сохранить 10 изображений**, чтобы пользователь до записи увидел итог: сколько файлов связано, а сколько ожидает разбора.

### Результат

Созданы независимые аналитические строки с методом и provenance; изображения связаны только с явно выбранными объектами. Пользователь получает CTA: **Открыть график только что импортированных данных**.

### Приёмка

- Разные названия и порядок столбцов обрабатываются по листам.
- Два анализа с одним именем точки, но разными методами, не объединяются автоматически.
- Исходный Excel не меняется без явного выбора и проверки hash.
- Каждую фотографию можно связать с несколькими `_analysis_id` или оставить неразобранной.

## Сценарий B. Найти апатиты в массиве и статье

### Цель

Найти все апатиты из конкретного массива и статьи, увидеть анализы вместе с шлифами и изображениями, передать только найденные данные в график.

### Старт

В глобальной строке поиска пользователь вводит: `апатит Кивгуба`.

### Экран поиска

Поисковая строка всегда сохраняется сверху. Рядом переключатель области:

- **Везде**;
- **Здесь · текущий Sample/массив**, если пользователь пришёл из рабочего стола.

Результат разделён на четыре вкладки:

| Вкладка | Содержимое |
|---|---|
| Анализы | Точки, минерал, метод, источник/статья, набор, QC |
| Объекты | Sample, массив, шлиф, зерно, связанные сущности |
| Изображения | Макрофото, PPL/XPL, BSE и карты |
| Источники / группы | Статья, DOI, рабочая группа, поколения и количество точек |

Если найдены разные статьи, сверху появляются строки-источники с числом точек, но они не считаются удалёнными или исключёнными.

Действия над результатом:

- **Построить график**;
- **Таблица статьи**;
- **Редактировать отбор**;
- **Открыть Sample/массив/шлиф**.

### Результат

В график передаются точные результаты запроса, включая `_analysis_id`; поиск не расширяется до всех апатитов проекта.

### Приёмка

- Поиск находит минерал, Sample, массив, статью/источник, шлиф и изображение по единому запросу.
- Кнопка графика использует полный результат поиска, даже если таблица показывает первые 1 500 строк.
- Переход «Открыть шлиф» сохраняет контекст найденного объекта.

## Сценарий C. Рабочий стол Sample и шлифа

### Цель

Понять, что связано с образцом, увидеть измеренные точки на фото шлифа и не перепутать методы.

### Старт

Пользователь открывает Sample `19 ТР-1` из обзора, поиска или списка образцов.

### Экран рабочего стола

Вверху: название Sample, массив, число анализов, изображений и методов. Под ним локальный поиск по текущему объекту и кнопка **Везде**.

Разделы:

- **Обзор**: паспорт Sample и недавние действия.
- **Анализы**: таблица, где каждая строка явно показывает Point, минерал, поколение, метод, источник и QC.
- **Изображения**: связанные фото и неразобранные материалы.
- **Шлифы и объекты**: PPL/XPL/BSE с маркерами точек.
- **Термодинамика**: только валидные для выбранного входа расчёты.

Клик по маркеру `P-12` выделяет соответствующие строки, не объединяя EPMA и LA-ICP-MS. Для двух методов одного физического места интерфейс показывает их как связанные измерения одной точки, но с отдельными строками и отдельным происхождением.

Действие **Построить график для выбранных точек** формирует точную выборку. Действие **Термодинамика** появляется только при допустимом составе входов. Для биминеральной задачи не создаётся ложная кнопка «быстрый расчёт».

### Приёмка

- Один маркер может ссылаться на несколько измерений разных методов.
- Клик по строке и по маркеру синхронизирует выделение.
- Неразобранные фото видны отдельно от связанных.

## Сценарий D. График сравнения с временным исключением статьи

### Цель

Сравнить апатиты из двух статей и собственных измерений, временно скрыть одну статью, сохранить воспроизводимый рисунок.

### Старт

Пользователь приходит из поиска или рабочего стола через **Построить график**.

### Экран графика

В верхней части отображается контекст: «Поиск · апатит Кивгуба · 83 точки». Рядом команда **Весь набор** доступна только как явное расширение выбора.

Левая колонка содержит:

- наборы и минералы;
- оси X и Y, предлагаемые только из реально доступных числовых колонок;
- группировку: источник, Sample, поколение, минерал, рабочая группа;
- видимость источников;
- параметры внешнего вида.

Правая часть занята диаграммой. При двух и более источниках группировка по источнику предлагается, но не включается принудительно.

Выключение источника в легенде или контроле «Что показывать» переводит его в `hidden_sources`. Точки остаются в DataUniverse и возвращаются по одному клику. QC, исходная химия и связи со шлифом не меняются.

После настройки доступны:

- **Настроить подробнее**;
- **Собрать 2-6 графиков**;
- **Сохранить рецепт**;
- **Экспорт PNG / SVG / XLSX + manifest**.

Manifest фиксирует точную выборку, оси, источники, группы, скрытые серии и стиль. Он позволяет затем открыть тот же график без реконструкции выбора вручную.

### Приёмка

- Скрытый источник не исключается из `analysis_ids` научной выборки.
- Новая точная выборка сбрасывает старые локальные presentation-фильтры, чтобы они не спрятали новые данные.
- Рецепт и export используют одну и ту же видимость источников.
- Переключение «Весь набор» требует явного действия пользователя.

---

## Порядок следующей реализации

1. Сделать в рабочем столе явное действие «Построить график для выбранных точек».
2. Усилить пакетный экран изображений: понятная очередь, множественные связи, «Входящие без связи».
3. Внести в импорт явное различение destinations и SHA-256 предупреждение перед записью в исходный Excel.
4. Добавить в поиск фасеты по минералу, массиву и статье, не нарушая точный handoff в график.
