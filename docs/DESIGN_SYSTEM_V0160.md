# PetroLab: дизайн-направление v0.16

Этот документ фиксирует выбранное направление интерфейса PetroLab и служит инструкцией для следующих изменений. Цель — спокойная локальная научная среда: данные и график остаются главным объектом экрана, а сложность открывается только по задаче пользователя.

Сквозные маршруты с состояниями, решениями и критериями приёмки описаны в [UX_SCENARIOS_V0160.md](UX_SCENARIOS_V0160.md).

## Основной принцип

Пользователь приходит не в «модули», а делать одно из семи действий:

1. **Обзор** — продолжить работу, открыть недавний Sample или массив.
2. **Образцы** — работать с конкретным Sample, точками, методами и связанными материалами.
3. **Породы** — открыть whole-rock образец: валовую химию, trace elements, изотопию, фотографии и связанные минералогические наборы.
4. **Поиск** — найти минерал, массив, Sample, точку, шлиф, статью или источник.
5. **Шлифы** — увидеть препарат, поля, изображения и привязанные точки.
6. **Анализы** — проверить и отредактировать строки с сохранением происхождения.
7. **Добавить** — импортировать Excel/CSV и изображения через единый безопасный маршрут.

Главная навигация содержит эти семь ежедневных входов. Остальные профессиональные инструменты остаются доступными в раскрывающемся «Дополнительно» или через контекстные действия, но не конкурируют с ежедневной работой.

## Визуальный язык

- Светлый нейтральный фон, поверхности белые или серо-зелёные; акцент — сдержанный тёмно-зелёный.
- Компактные границы и углы 3–8 px; без декоративных градиентов и «маркетинговых» карточек.
- Один экран должен явно показывать текущий проект и объект работы.
- Заголовок, локальный поиск, отбор и результат располагаются в устойчивом вертикальном порядке.
- Число и статус показываются короткими бейджами; объяснение — в подсказке или вторичном тексте.
- На узком экране интерфейс не перекрывается: таблицы сохраняют горизонтальную прокрутку, а боковая панель прокручивается отдельно.

## Непереговорные инварианты данных

- EPMA/WDS, EDS, LA-ICP-MS, TIMS и иные методы остаются отдельными измерениями; UI не объединяет их в «одно значение».
- Источник, лист, строка и устойчивый `_analysis_id` не маскируются при фильтрации или редактировании.
- Оригинальный Excel не меняется неявно. Рабочая копия PetroLab и обратная запись в исходный файл должны быть визуально различимы.
- Импорт книги с несколькими листами проходит общий preflight; нельзя показывать частичный успех как финальный результат.
- Неоднозначные FeO/FeOt/Fe2O3 и неизвестные единицы требуют явного решения пользователя.
- Выключение статьи, источника, серии или точки на графике — обратимое **представление**, а не изменение QC, базы или происхождения.
- Для графика сохраняется точная научная выборка (DataUniverse); локальные настройки видимости не должны её расширять или сужать молча.

## Основные сценарии

### 1. Импорт Excel и изображений

`Добавить` → файл → листы и семантическое сопоставление → общий preflight → проверка строк → сохранение в PetroLab → опциональная привязка изображений.

Для каждого листа отображаются минерал, строка заголовка, метод, Sample/Generation и состояние проверки. Несвязанные фотографии попадают во «Входящие без связи», а не исчезают и не привязываются автоматически.

### 2. Sample и шлиф

`Образцы` → Sample/массив → локальный поиск → вкладки «Обзор», «Анализы», «Изображения», «Шлифы и объекты», «Термодинамика».

Точка на фото/шлифе связывается с конкретными строками анализов. «Термодинамика» показывается только для допустимых мономинеральных или минерал–расплав задач; биминеральные методы не предлагаются как быстрый маршрут.

### 3. График

График запускается из текущего Sample, точного результата поиска или после импорта. Передаются точные `dataset_id` и `_analysis_id`; пользователь не выбирает их заново.

Рабочая область графика сначала предлагает безопасный XY-старт по реально доступным числовым столбцам. Затем пользователь может:
- сменить оси и тип графика;
- сгруппировать точки по источнику, Sample, поколению, минералу или рабочей группе;
- временно скрыть статью/источник;
- перейти в расширенный редактор, multi-panel или публикационный экспорт;
- сохранить состояние как воспроизводимый рецепт с manifest.

### 4. Универсальный поиск

Запрос должен работать по Sample, точке, зерну, минералу, поколению, методу, массиву, статье/источнику, шлифу и изображению. Результаты разделяются на анализы, объекты, изображения, источники/группы; действия «Построить график», «Таблица статьи» и «Редактировать отбор» используют один и тот же точный результат.

## Правила реализации

- `app.py` остаётся тонкой оболочкой; маршруты и UI-компоненты живут в `petrolab/ui/`.
- Изменения навигации не удаляют старые маршруты: recipes, deep links и существующие сценарии должны продолжать работать.
- Новый пользовательский текст — по-русски; Python API — по-английски.
- Изменение визуального сценария должно сопровождаться небольшим тестом контракта и проверкой запуска Streamlit.
- Нельзя добавлять научные пороги, формулы или классификационные границы в общий UI-рендерер.

## Критерии приёмки первой итерации

- В боковой панели видны ровно шесть ежедневных действий, включая «Шлифы» и «Добавить».
- «Дополнительно» не пропадает и содержит прямой доступ к графикам, расчётам, статистике и публикационным инструментам.
- Существующие маршруты `plots`, `search`, `workspace`, `thin_section`, `analyses` и `add_data` остаются адресуемыми.
- Из поиска и контекстных экранов уже можно передать точную выборку в график.
