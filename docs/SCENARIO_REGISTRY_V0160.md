# Реестр пользовательских сценариев PetroLab v0.16

Этот реестр собран из утверждённых пошаговых сценариев проекта. Он служит критерием для согласования веток: функциональность переносится только тогда, когда она сохраняет спокойную task-first модель Product Design v0.16.

## Общие правила

- Исходные данные, provenance и метод измерения не переписываются действиями интерфейса.
- Точный отбор передаётся между поиском, Sample, шлифом и графиками по `_analysis_id`, без расширения до всего набора.
- Одна физическая точка может иметь EPMA/EDS/LA, но это разные измерения с отдельными строками.
- Отдельный BSE связывается с одним конкретным полем, а не неявно со всем шлифом.
- Верхняя навигация отвечает ежедневным действиям: Обзор, Образцы, Породы, Поиск, Шлифы, Анализы, Добавить.

## S1. Книга Excel → проверка → фотографии

### Старт

Пользователь нажимает **Добавить**, загружает XLSX/XLSM и выбирает нужные листы.

### Шаги

1. Для каждого листа подтверждает строку заголовков, минерал или тип whole-rock, метод, Sample, Point и Generation.
2. Видит нормализованный preview: оксиды и trace elements с единицами; пустые значения и `<DL` остаются исходными состояниями.
3. Разрешает неоднозначности FeO/FeOt/Fe2O3, единиц и дубликатов до сохранения.
4. Сохраняет либо в базу и рабочую копию PetroLab, либо в связанный исходный Excel после SHA-256 проверки.
5. Переходит **Далее: изображения**, загружает пакет, для каждого файла выбирает тип и точные связи с Sample/шлифом/зерном/точками либо **Оставить без связи**.
6. Сохраняет пакет одним действием и получает CTA к графику только что импортированных данных.

### Приёмка

- Листы с разным порядком и именами колонок обрабатываются отдельно.
- Минеральные и whole-rock листы не подменяют друг друга.
- Неразобранные изображения остаются во входящих.
- Внешний Excel не перезаписывается при изменившемся hash.

### Реализация

Основа: intake и image wizard из ветки `fix/post-release-audit-20260817`; визуальная оболочка и основной вход: Product Design v0.16. При согласовании переносится механика без старого конкурирующего меню.

## S2. Найти минерал / массив / статью → точная выборка

### Старт

Пользователь вводит, например, `апатит Кивгуба`.

### Шаги

1. Поиск действует по текущему объекту или по всему проекту.
2. Результаты разделены на **Анализы**, **Объекты**, **Изображения**, **Источники / группы**.
3. Можно открыть Sample, массив, шлиф, таблицу статьи либо построить график.
4. При сравнении статей источник можно временно скрыть; он остаётся в базе и возвращается одним действием.
5. В график уходят точные `_analysis_id` найденного результата.

### Приёмка

- Запрос объединяет минерал, Sample, массив, шлиф, фото и публикацию.
- Скрытие статьи не меняет raw data и provenance.
- Поиск не расширяет отбор до всего проекта.

### Реализация

Product Design v0.16: Object Workspace, exact handoff и source visibility.

## S3. Sample → шлиф → поле → точка → BSE

### Старт

Пользователь открывает Sample или шлиф из поиска.

### Шаги

1. Добавляет PPL/XPL/BSE к одному шлифу.
2. На базовом снимке рисует только **прямоугольник** или **квадрат** и сохраняет поле.
3. Выбирает активное поле.
4. Кликает место анализа, добавляет подпись и связывает один или несколько аналитических рядов.
5. Привязывает маленький BSE к выбранному полю; повторная привязка явно переносит BSE в другое поле.
6. Клик по точке выбирает все измерения одной физической позиции и передаёт их в график.

### Приёмка

- Контуры произвольной формы не предлагаются.
- Точка хранит связь с полем, если оно выбрано.
- BSE принадлежит одному полю одного шлифа.
- EPMA/EDS/LA остаются отдельными строками с общим физическим контекстом.

### Реализация

`product/v0160-intake-search-petrography-rocks`: прямоугольная разметка, связь `slide_field_bse_images`, explicit BSE field binding.

## S4. Выбор точек → связанные графики → публикация

### Старт

Пользователь приходит с точной выборкой из поиска, Sample или шлифа.

### Шаги

1. Настраивает 2–10 панелей: бинарные, треугольные и spider.
2. Выделяет точки кликом, рамкой или лассо на любой совместимой панели.
3. Видит те же выделенные точки на всех панелях.
4. Кодирует **цвет** и **значок** независимыми характеристиками.
5. Сохраняет рабочую группу и воспроизводимый recipe/manifest.
6. Передаёт mixed-компоновку в редактор публикации рядом с шлифами и фотографиями.

### Приёмка

- Работает и для минералов, и для пород.
- Скрытый источник остаётся в научной выборке.
- Publication layout включает треугольные и spider-панели.
- Manifest хранит выборку, оси, видимость источников и стили.

### Реализация

Product Design v0.16 + `product/v0160-intake-search-petrography-rocks`.

## S5. Рабочий стол породы

### Старт

Пользователь открывает **Породы** из основной навигации или переходит из поиска.

### Шаги

1. Видит паспорт Sample: массив, литология, возраст, полнота данных.
2. Открывает валовую химию, trace elements, изотопию, фотографии/шлифы и связанные минералогические наборы.
3. Переходит к whole-rock диаграммам и сравнению с литературой.
4. Редактирует и экспортирует карточку, не смешивая whole-rock и минералогические строки.

### Приёмка

- Породы доступны напрямую, а не в скрытом техническом маршруте.
- Повторные определения и источники сохраняются.
- Связанные минералы видны, но не подменяют chemistry породы.

### Реализация

`product/v0160-intake-search-petrography-rocks`; опирается на staging-механику `feature/v0154-universal-staging-import`.

## S6. Прозрачная научная работа и воспроизводимость

- Минерал можно исправить без скрытой подмены исходного ряда.
- Формулы/APFU, термобарометрия и классификации появляются только при валидных входных данных.
- Выбросы видны в контексте и исключаются обратимо.
- Рецепты графиков, публикационные таблицы и экспорт сохраняют provenance и точный состав выборки.
